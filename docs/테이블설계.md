# Ledger V3.0 테이블 설계

18개 테이블. 실제 DDL은 `src/main/resources/db/migration/V1__init_schema.sql`.

이 문서의 테이블·컬럼명은 대문자로 적지만 **물리 테이블명은 전부 소문자**다 (ADR-045 — 리눅스 MySQL 은 대소문자를 구분하므로 V1 이 소문자로 만든다. 컬럼명은 어느 OS 든 구분하지 않아 그대로).

## 마이그레이션 정책

- V1 은 **2026-09-18 운영(EC2)에 적용됨** — 맥·CI·EC2 세 환경 모두 이 파일 하나로 19테이블(18 + `flyway_schema_history`)
- 이후 스키마 변경은 V2, V3 순서로 새 마이그레이션 파일 추가. V1 은 더 이상 고치지 않는다 (2026-09-18 소문자 전환은 데이터가 없어서 가능했던 마지막 예외, ADR-045)
- 운영 적용: V2 `USERS.USER_WITHDRAWN_AT`(2026-09-23, ADR-052) · V3 `REFRESH_TOKENS.FAMILY_ID`·`REVOKED_AT`·`TOKEN_HASH` UNIQUE·`FAMILY_ID` 인덱스(2026-09-25, ADR-055). 새 V 파일은 forward-only(ADR-053)
- **노션 "Ledger V3.0 테이블 설계도" 페이지와 동기화** — 이 파일을 고치면 같은 커밋 때 노션도 (2026-09-27 동기화)

## 공통 관례

**제약**
- `(PROVIDER, PROVIDER_USER_ID)` UNIQUE — 동일 소셜계정 중복 연동 방지
- `(USER_NUM, PROVIDER)` UNIQUE — 한 회원이 같은 제공자를 두 번 연동하는 것 방지

**주의** — 이미 이메일/비밀번호로 가입된 계정과 동일 이메일의 소셜 로그인 시도는 자동 연동 처리하지 않음.

## 인덱스

| 테이블 | 인덱스 | 용도 |
|---|---|---|
| PERSONAL_TRANSACTIONS | (USER_NUM, TRANS_DATE) | 월별 조회 / 통계 |
| GROUP_TRANSACTIONS | (GROUP_NUM, TRANS_DATE) | 그룹 통계 |
| GROUP_TRANSACTIONS | (PERIOD_NUM) | 회차별 정산 계산 |
| MERCHANT_PROFILES | (USER_NUM, MERCHANT_NAME) | 유사 상호명 검색 시작점 |
| GROUP_MEMBERS | (USER_NUM, MEMBER_STATUS) | "소속 방 10개 제한" 검증 |
| EXPENSE_LOGS | (GTRANS_NUM, CREATED_AT) | 특정 내역 변경 이력 조회 |
| REFRESH_TOKENS | (USER_NUM, REVOKED_YN) | 전 세션 폐기(비번 변경·탈퇴) — 그 사용자의 살아 있는 토큰 전부 |
| REFRESH_TOKENS | (FAMILY_ID) | 유예 판정("살아 있는 줄 있나") · 패밀리 전체 폐기 (V3) |
| REFRESH_TOKENS | UNIQUE (TOKEN_HASH) | 재발급마다 쿠키 원문 → 해시 → 이 칸으로 찾는다. 해시 하나 = 토큰 한 장 (V3) |
| RECEIPT_ANALYSIS | (ANALYSIS_STATUS, CREATED_AT) | 스케줄러 — '처리중' 15분 경과 건 청소 |
| GROUP_MERCHANT_PROFILES | (GROUP_NUM, MERCHANT_NAME) | 그룹 상호명 검색 시작점 |
| AI_USAGE_LOGS | (USER_NUM, CREATED_AT) | 유저당 하루 10회 카운트 |

인덱스 이름은 V1 의 `IDX_*` / `UK_*` 참조. 위 3개는 V1 에 있었으나 문서에 빠져 있던 것 (2026-09-18 실측 보강)
