# Ledger V3.0 기획서

> 노션 "AI 스마트 개인 및 공동 가계부 (Ledger V3.0)" 페이지와 동기화 — 이 파일을 고치면 같은 커밋 때 노션도 (2026-09-27 동기화). 노션은 문장형, 이 파일은 요약형이라 문장은 달라도 사실은 같게

## 한 줄 요약

영수증·결제내역 캡처만 올리면 AI가 등록해주고 지도로 소비 위치를 보는 가계부 + 가족·연인·모임용 1/N 자동 정산 공동 가계부. 화면은 정적 파일(Vanilla JS), 데이터는 `/api` JSON — Spring Boot 한 프로세스가 둘 다 서빙(별도 프론트 서버 없음). PWA 적용.

## AI 자동 분석 파이프라인

### 왜 캡처 OCR 인가 — 규제상 사실상 유일한 길

카드·계좌 내역을 자동으로 가져오는 정식 경로는 마이데이터뿐인데 **허가제**(본인신용정보관리업)라 개인 프로젝트는 신청 자체가 안 된다. 오픈뱅킹은 계좌 거래내역만 있고 **카드 승인내역이 없다**. 그래서 사용자가 이미 받고 있는 결제 알림·뱅킹앱 화면을 캡처해 올리면 OCR 로 읽는 방식이 개인 개발자가 쓸 수 있는 유일한 자동화다. 카드사 CSV 업로드는 보완 후보(백로그).

### 등록 진입점 — 캡처 / 직접 입력

거래 등록 버튼은 **📷 캡처 올리기 / ✏️ 직접 입력** 두 진입점 (2026-09-18). 설정으로 기억하는 모드 토글은 두지 않는다 — AI 는 하루 10회 제한이라 "쓸 때만 누르는 것"이 자연스럽고, 상태가 없으면 테이블·API 가 늘지 않는다. AI 실패 시에도 같은 직접 입력 화면으로 떨어진다(실패 대응 표). 사용자별 기본 등록 방식 설정은 백로그.

### 1단계 — 텍스트 추출

네이버 Clova **일반 OCR** 사용 (영수증 특화 OCR 대신).

> 뱅킹앱·결제알림 캡처 비중이 높을 것으로 판단. 월 100회 무료.

### 2단계 — 파싱

1. 정규표현식으로 금액 / 날짜 / 결제대상을 먼저 시도
2. 실패했을 때만 LLM 보조 호출

은행앱별 패턴은 실제로 부딪히며 하나씩 등록해나갈 계획.

### 3단계 — 분류

상호명 임베딩(코사인 유사도)으로 본인 과거 내역을 검색한다.

- **과거 내역이 있으면** → 그때 쓴 카테고리·메모를 추천 (LLM 미호출)
- **없으면** → LLM에 유저 카테고리 전체 목록을 주고 기존 중 선택하거나 신규 제안하게 함

신규 카테고리 제안 시 확인창(`'구독료' 만들까요?`)을 띄우고, 승인하면 생성 / 거절하면 미분류로 등록한다. 기존 카테고리와 문자열·임베딩 유사도를 체크해 중복 제안을 막고, `미분류`는 시스템 예약어라 제안 자체를 차단한다.

### 원칙

- **AI 결과는 바로 저장하지 않는다.** 유저가 확인·수정한 뒤 저장 (돈 관련이라 100% 자동 저장은 위험)
- 개인은 유저 단위, 공동은 그룹 단위로 학습 프로필을 분리. 공동 분석 전에 멤버 여부 확인

### 실패 대응

| 상황 | 처리 |
|---|---|
| 과거 내역 없음 | 임베딩 건너뛰고 LLM 직행 |
| OCR·LLM 실패 | "직접 입력해주세요"로 수동 입력 화면 이동 |
| 확인창 미응답 | 정리 스케줄러가 처리 |

## 공동 가계부 / 정산

### 정산 사이클

- **매월 정산형** — 월간 초기화
- **자유 정산형** — 수동 초기화

### 1/N 계산

```
인당 부담액 = 총지출 ÷ 인원
개인 수지   = 실제 낸 금액 - 부담액
             (+) 받을 사람 / (-) 낼 사람
```

소수점은 내림 처리하고, 자투리는 제일 많이 받을 사람이 덜 받아 합을 0으로 맞춘다.

### 그리디 매칭

최대 채권자와 최대 채무자를 1:1로 우선 매칭해 송금 횟수를 최소화한다.
최소 송금 횟수를 보장하는 알고리즘은 아니지만 2~10명 규모에선 결과가 거의 동일하다. 완전탐색은 백로그.

### 방장 권한

초대 / 방 정보 수정 / 방 삭제 / 정산 켜고 끄기 / 강퇴 / 방장 넘기기.
방장이 나가면 **가장 먼저 들어온 멤버에게 자동 위임**된다.

### 제한 및 정책

- 1인 최대 10개 방, 방당 최대 50명
- 정산이 안 끝난 돈이 남아 있어도 강퇴·탈퇴를 시스템에서 막지 않는다. 나간 사람의 지출은 "그룹에 없는 사용자"로 표시
- **로그 박제** — 공동 지출 수정·삭제 시 로그 테이블에 강제 기록. 방장 포함 아무도 삭제할 수 없다
- 지난 달·보관된 과거 데이터는 방장도 수정 불가

## 지도 / 카테고리 / 통계 / PWA

### 카카오맵

- 핀 이모지는 카테고리 이모지를 재사용 (없으면 기본 핀)
- 위치는 선택 입력 (카카오맵 장소검색)
- 축소 시 클러스터링, 확대 시 이모지 핀
- 개인 지도와 공동 지도를 분리. 별도 필터 탭 없이 현재 장부 + 월 선택 UI를 따름

### 카테고리

- **대분류 - 소분류 2계층만.** 더 깊으면 입력이 귀찮고 AI 분류 정확도가 떨어짐
- 이모지는 생성 시 한 번 선택
- 자주 쓰는 카테고리명엔 서버 고정 목록으로 기본 이모지를 추천

### 소셜 자극

유저 ID 검색으로 '공개' 가계부를 열람할 수 있다 (위치 정보도 함께 노출됨).

### 통계

- 이달 카테고리별 봉투 — 대분류 ⊃ 소분류, 비율은 부모 대비 (ADR-039)
- 수입 대비 지출 — 지출 ÷ 수입 × 100. 수입 0 이면 `null`, 화면은 `-` (ADR-039)
- 최근 6개월 개인·공동 추이 그래프 — 보는 달 포함 롤링 6개, 빈 달 0

### PWA

모바일 우선 화면. 설치 조건상 HTTPS 필수.

## 인증 / 보안

### 토큰

- JWT **Access 15분 / Refresh 14일**
- Refresh 는 `HttpOnly` · `Secure` · `SameSite=Strict` · `Path=/api/auth` 쿠키 + 서버 저장(`refresh_tokens`, 원문 아닌 SHA-256). 원문은 `SecureRandom` 32바이트 (로그아웃·비번변경 시 즉시 무효화)
- **Refresh 로테이션 + 재사용 탐지** — 재발급마다 새 토큰, 옛 토큰 폐기. 폐기된 Refresh 로 재발급을 시도하면 탈취로 간주하고 **그 로그인(패밀리, `FAMILY_ID`)의 토큰 전부**를 폐기한다 — 계정 전체가 아니라서 다른 기기는 그대로. 응답 유실·탭 두 개 때문에 폐기 30초 안 + 같은 패밀리에 살아 있는 토큰이 있으면 봐준다(유예). 비번 변경·탈퇴는 그 계정의 전 세션 폐기. 상세는 ADR-055

### 로그인

- 소셜 로그인은 **배포 후** 네이버 → 구글 순 (개발자 콘솔에 배포 URL 등록이 선행). 카카오 로그인은 하지 않는다 (2026-09-18. 카카오맵은 지도 API 라 별개로 유지). 로그인 후엔 자체 JWT 발급
- 동일 이메일의 기존 계정이 있어도 **자동 연동하지 않고 별도 안내**
- 로그인 실패 5회 초과 시 30분 잠금, 성공 시 카운트 초기화. 계정만 기준이면 남의 계정을 일부러 잠글 수 있다 — **계정+IP 조합 또는 지수 백오프** 중 구현 때 결정
- 로그인 빈도 자체는 Refresh 14일로 낮춤(기기당 2주 1회). 지문·FaceID는 패스키(WebAuthn, 웹·PWA 공통 표준)로 비밀번호 대체 — Sprint 5 이후
- **Access 토큰은 메모리(JS 변수)에만** 둔다. 새로고침 시 Refresh 쿠키로 재발급. `localStorage` 는 XSS 한 번에 토큰이 새어 나간다 — 지금 구현(`apiClient.js`)은 `localStorage` 이며 Refresh 쿠키를 붙일 때 같이 옮긴다
- **CSRF** — Refresh 쿠키는 `SameSite=Strict`. 쿠키를 읽는 엔드포인트는 `/refresh` 하나라 그곳만 CSRF 방어. 나머지 API 는 헤더 토큰이라 대상이 아니다 (지금 `csrf.disable()` 은 그래서 맞음)

### 이메일 가입 인증 / 비밀번호 재설정

- **가입 시 이메일 인증 링크** — 인증 전엔 로그인 불가 (2026-09-18). 남의 이메일로 가입해 그 사람에게 재설정 메일이 가는 경로를 막는다 — reCAPTCHA 는 봇만 막는다. 비번 재설정과 같은 SES · 같은 `AUTH_VERIFICATIONS` 테이블
- 재설정 이메일 링크 30분 유효, 1회용
- 같은 이메일로 1시간에 3회를 초과하면 발송 중단 (가입 인증 메일도 동일)

### 봇·남용 방지

- 회원가입·비번재설정에 reCAPTCHA
- 같은 IP에서 단시간 다수 가입 차단, 가입 IP 기록
- 유저 검색 기능도 호출 횟수 제한

### API 호출 제한

앱 메모리 카운터 + Nginx `limit_req` 이중 구성. 서버 한 대라 카운터를 공유할 상대가 없다 — Redis 는 서버가 2대가 되는 시점에 (카운터를 인터페이스로 감싸 그 클래스 하나만 교체되게).

| 대상 | 제한 |
|---|---|
| 일반 API | 유저당 분당 60회 (조정 예정) |
| AI 분석 | 유저당 하루 10회 + 앱 전체 월 사용량 카운터로 Clova 무료 한도 관리 |

초과 시 429. AI 호출 이력은 메모리 카운터가 재시작 때 날아가므로 DB에 별도 기록한다.

### 업로드

10MB 이하, jpg/jpeg/png만, 파일 시그니처 검사.

### 기타

- 권한 검증 (작성자 본인 확인)
- AI 데이터 격리 (조회 조건에 `USER_NUM` 강제)
- MyBatis `#{}` 바인딩 원칙
- CORS는 프론트 도메인만 허용

## 데이터 무결성 / 스케줄러

### 무결성

- 소프트 딜리트 (`use_yn`). 단 **회원 탈퇴는 30일 유예 뒤 계정째 물리적 삭제** — 유예 중 로그인하면 취소, 매일 03:30 스케줄러가 지운다 (ADR-052, 2026-09-23)
- 금액 0/음수 화면 + 서버 이중 검증
- **낙관적 락**(`version` 컬럼) — 비관적 락 대신. 충돌 빈도가 낮은 실사용 패턴을 고려
- **트랜잭션 분리** — AI 분석 몇 초 동안 DB 커넥션을 붙잡지 않도록 임시 저장과 최종 저장을 분리
- 예외 처리를 한곳에 모아 응답 형식 통일

### 스케줄러

| 주기 | 작업 |
|---|---|
| 30분 | 15분 지난 '처리중' 분석 → 실패 처리 + S3 원본 삭제 |
| 하루 1회 | 미연결 S3 이미지(1일 이상) 삭제 |
| — | 7일 지난 실패·처리중 분석 삭제 |
| — | 만료 인증토큰 삭제 |
| — | 만료·무효 Refresh 삭제 |
| — | 30일 지난 대기 초대장 → 무효 |
| — | 90일 지난 AI 호출 이력 삭제 또는 요약 |

지출·정산·감사로그는 정리 대상에서 제외한다.

## 인프라 / 예산

### 구성

EC2 ARM t4g(지금 small 2GB → AI 도입 때 medium 4GB — ADR-002 보완) **한 대**에 Spring Boot + MySQL + 임베딩 모델을 전부 구동. **Redis 는 두지 않는다** — 서버 2대부터 (2026-09-18). 스왑 대신 여유 메모리 확보를 선택 (앱 기동 후 available 608Mi 실측). 이미지는 S3.

- 도메인 `dotoree.app`(Cloudflare Registrar, DNS only) + Nginx + Let's Encrypt HTTPS. 보안 헤더 4종 중 HSTS · `X-Frame-Options` · `X-Content-Type-Options` 는 Spring Security 기본값, **CSP 만 추가**(`SecurityConfig`, 외부 출처 0). Nginx 는 경계 — 80→443, `/actuator` 는 health 만, IP 직접 접속 거부 (ADR-049, 2026-09-21)
- GitHub Actions — `build → qa(192케이스 게이트) → deploy`. main 푸시만 배포 (ADR-042)
- **이중화 없음** — 단일 장애점은 감수(ADR-002). 대신 systemd 자동 재시작 / DB 일 1회 백업 → S3 / UptimeRobot 외부 감시 + Healthchecks.io 작업 감시(백업·인증서, ADR-051)로 "꺼졌을 때"의 피해(다운 몇 분, 데이터 유실)를 막는다. 이중화는 실제 사용자가 생겨 다운타임이 비용이 될 때 재검토
- Swagger(springdoc) — **Sprint 2 부터 도입** (API 가 늘기 시작하는 시점. 지금 `build.gradle` 에 없음). Actuator 는 `health` 만 노출, 외부 확인 경로는 1차 배포 3단계에서 결정. `/actuator/env` 는 절대 열지 않는다
- **임베딩** — 가벼운 한국어 문장 임베딩 모델을 서버에서 직접 구동. 벡터는 MySQL JSON에 저장하고 앱에서 코사인 계산 (유저당 수백 개 수준이라 충분)
- **LLM** — Ollama 경량 모델을 서버 내 구동. 정규식 실패·신규 상호일 때만 호출

Ollama 도입으로 **t4g.medium** 이 되면 EC2 약 47,000원 → AWS 소계 약 61,000원, 합계 월 약 6.3만원 (원래 예산과 비슷한 돈으로 4GB).

유형 변경은 같은 ARM 계열 안에서만 — small ↔ medium (중지 → 변경 → 시작 5분, 탄력적 IP 라 주소 그대로). ARM ↔ x86 은 새로 만들어야 한다.
