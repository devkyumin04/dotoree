## Sprint 1 — 진행 중: 1차 배포

설계 결정은 ADR-042 · 046 · 047 · 048 참조. 순서는 **배포할 물건(yml) → 서버 → 자동 배포 → 검문소 → 운영 보강**.
3과 4를 나눈 이유 — 같이 만들면 실패했을 때 배포 문제(SSH·systemd)인지 테스트 문제인지 구분이 안 된다.

| 단계 | 상태 |
|---|---|
| 1. 운영 프로파일 — yml 분리 (직접). 기동 확인: 프로파일 없음 → SQL 로그 없음 / `local` → SQL 로그 찍힘 (2026-09-17) | ✅ |
| 2. EC2 세팅 — 타임존·MySQL·Java·systemd. **프로파일 도입은 여기서 완성** (직접) | ✅ 2026-09-18 (2-1~2-5) |
| 3. CD 최소판 — jar 전송 + 재시작. 배포 1회 성공 확인 (직접) | ✅ 2026-09-20 (3-1~3-7, ADR-046·047·048, 트러블슈팅 13·14) |
| 4. 게이트 — `_lib.sh` 비대화 모드(위임) + 워크플로 QA 잡 + `needs:` (직접) | ✅ 2026-09-20 (4-1~4-5, CI #52~#55) |
| 5. 운영 보강 — HTTPS / DB 백업 크론 → S3 / UptimeRobot / 타임존 3계층 확인 / SES 샌드박스 해제 신청 | 🟡 5-1~5-4 ✅ 2026-09-21 (도메인·Nginx·HTTPS·actuator 차단·CSP, ADR-049) · 5-5 ✅ 2026-09-22 (DB 백업 → S3, ADR-050) · 5-6 ✅ 2026-09-22 (감시 3종 — UptimeRobot + Healthchecks.io, ADR-051). 남은 것 — SES 신청 |

### 1단계 가이드 — 운영 프로파일 (yml)

- **규칙 하나** — `application-{이름}.yml` 은 그 프로파일이 켜졌을 때만 읽히고, 공통 `application.yml` **위에 덮어씌워진다(merge)**.
  그래서 프로파일 파일엔 **공통과 다른 값만** 적는다. 전체를 복사해 두면 mybatis 설정 하나 바꿀 때 두 파일을 고치게 된다 (ETC 위반)
- 분류 — "맥북과 EC2 에서 값이 달라야 하는가"

| 덩어리 | 달라야 하나 | 위치 |
|---|---|---|
| `spring.datasource` | 아니오 — 세 환경(맥북·CI·EC2) 모두 자기 컴퓨터의 MySQL(`localhost`), 계정·비번은 이미 `${ENV}` | 공통 |
| `mybatis` / `server.port` / `jwt` | 아니오 | 공통 |
| `logging.level.com.kyumin.ledger.mapper: DEBUG` | 예 — 운영에선 사용자 금액·메모가 SQL 바인딩 값으로 로그에 남는다 | `application-local.yml` |

- 할 일 — ① `application-local.yml` 엔 `logging:` 덩어리 3줄만 ② `application.yml` 에서 그 3줄 삭제 ③ STS Run Configuration → Profile 칸에 `local`
  - ③은 저장소가 아니라 STS 에 저장된다. 새 PC·STS 재설치 후 "SQL 로그가 안 보인다"면 Profile 칸부터 확인
- 검증 — `local` 켜고 기동: 로그에 `The following 1 profile is active: "local"` + 조회 시 SQL 찍힘.
  Profile 비우고 기동: `No active profile set` + SQL 안 찍힘 (= 운영의 모습)
- **기본값은 운영에 안전한 쪽** — DEBUG 를 공통에 두고 prod 에서 끄는 구조는 프로파일 지정을 깜빡하면 DEBUG 가 켜진 채 운영된다.
  공통엔 없고 local 에서만 켜면, 깜빡했을 때 "SQL 로그가 안 보임"으로 눈에 띄게·안전하게 실패한다
- `application-prod.yml` 은 **지금 안 만든다** — 넣을 값이 없다 (YAGNI). 파일이 없어도 `prod` 프로파일로 기동된다.
  운영에서만 다른 값이 처음 생길 때(Refresh 쿠키 `Secure`, S3 버킷, SES 발신 주소) 만든다
- DB URL 은 yml 에 그대로 — 세 환경에서 값이 같고 비밀이 아니다. `${DB_URL:...}` 는 DB 를 인스턴스 밖으로 옮길 때 그 한 줄만 바꾸면 된다 (ADR-042)
- CI 는 고칠 것 없음 (프로파일 없이 돈다)

### 2단계 가이드 — EC2 세팅

- **2-1 인스턴스 생성 — ✅ 2026-09-17** (ADR-002 보완). 값은 저장소에 적지 않는다 — IP·키 위치는 저장소 밖 개인 보관처에
  - `ledger-prod` / 서울 / Ubuntu 26.04 LTS arm64 / **t4g.small**(2GB — medium 으로 만들었다가 같은 날 내림) / 30GB gp3 / 크레딧 사양 Standard / 탄력적 IP 연결
  - 키 페어 `ledger-admin`(ED25519, `.pem`) — 내 접속용. CD 용 키는 3단계에서 따로
  - 보안그룹(`launch-wizard-1`) — 22(**내 IP 만**) / 80 / 443. **8080·3306 은 열지 않는다** (앱은 Nginx 뒤, DB 는 localhost 전용)
  - 주의 — 집 IP 가 바뀌면(공유기 재시작 등) SSH 가 타임아웃 난다. 보안그룹 인바운드 22번의 소스를 "내 IP"로 다시 지정
  - SSH 첫 접속 확인 ✅ / 예산 알림 `ledger-monthly` 월 $30 ✅ / 루트 MFA ✅ (폰 OTP, 내장 브라우저 로그인까지 확인). 만든 것 전체와 조작법은 [aws-인프라.md](aws-인프라.md)
  - 접속 배너의 시스템 시각이 **UTC** 였다 — 2-2 에서 OS 타임존부터 바꾸는 이유 (ADR-026)
- **2-2 타임존 → MySQL — ✅ 2026-09-17** (ADR-043 · ADR-044)
  - 순서가 중요 — **OS 타임존 먼저**(`timedatectl set-timezone Asia/Seoul`) → 그다음 MySQL 설치. MySQL 기본 `time_zone=SYSTEM` 이 OS 를 따라간다 (ADR-026 — JDBC `serverTimezone` 옵션으로 덮지 않는다)
  - 커널 업그레이드가 걸려 있으면(`Pending kernel upgrade`) **MySQL 설치 전에 재부팅**한다. 앱이 올라간 뒤엔 재부팅이 곧 서비스 중단이고, 옛 타임존으로 떠 있던 프로세스도 이때 정리된다
  - 실측 — OS `Asia/Seoul (KST, +0900)` · NTP active / MySQL **8.4.11**(`apt-cache policy` Candidate) · `active (running)` · `enabled`(재부팅 자동 기동) / `@@global.time_zone = SYSTEM` · `NOW()` 한국 시각
  - 보안 — `mysql_secure_installation` 실행. 다만 우분투 패키지는 **익명 사용자도 원격 root 도 처음부터 없다**(설치 직후 `mysql.user` 실측). 구멍을 막는 작업이라기보다 확인 작업이다. `root@localhost` 는 `auth_socket` 유지 (ADR-043)
  - `ledger_db` + 앱 전용 계정 `ledger_app`@`localhost` — 맥·CI 와 **같은 이름**, 비밀번호만 새로 만든 값. 테이블은 만들지 않는다 (첫 기동 때 Flyway `V1`)
  - 권한 확인 — `SHOW GRANTS` 가 `USAGE ON *.*` + `ALL PRIVILEGES ON ledger_db.*` 두 줄. `USAGE` 는 "접속만 가능" 이라는 뜻이라 정상
  - collation 은 **명시하지 않는다** — 기본값 `utf8mb4_0900_ai_ci` 가 그대로 세 환경 공통값이 된다 (ADR-044)
  - 메모리 — 설치 직후 `free -h` available 879Mi, 스왑 0. **2-5 에서 앱을 올린 뒤 available 이 300Mi 아래면 1GB 스왑 파일**을 만든다 (그때 판단)
- **2-3 Java 17 · 전용 실행 유저 — ✅ 2026-09-17**
  - `openjdk-17-jre-headless` **17.0.20** (arm64, universe). **JRE 로 충분** — 빌드는 맥·CI 가 하고 서버는 `java -jar` 실행만 한다. 판단 기준은 "이 컴퓨터가 하는 일이 빌드인가 실행인가". 진단 도구(`jstack`·`jcmd`)가 필요해지면 그때 JDK 를 얹는다 (YAGNI)
  - `-headless` 는 화면 출력용 라이브러리(X11·사운드)를 뺀다. 모니터 없는 서버엔 쓸 일이 없고 `ImageIO` 는 그대로 된다 (Sprint 2 영수증 처리 영향 없음)
  - 주의 — `java` 미설치 상태에서 나오는 "can be installed with" 목록은 command-not-found 의 별도 스냅샷이라 버전이 뒤처진다. 실제 설치 값은 `apt-cache policy` 의 Candidate
  - 실행 유저 — `sudo useradd --system --shell /usr/sbin/nologin --no-create-home ledger`
    - 실측 `ledger:x:999:987::/home/ledger:/usr/sbin/nologin` — UID 999(<1000) 시스템 계정 / 셸 `nologin` / `/home/ledger` 는 **경로만 적힌 것이고 디렉토리는 없다**(`mysql` 계정의 `/nonexistent` 와 같은 성격)
    - **계정은 사람만 쓰는 게 아니다** — 이미 이 서버의 MySQL 이 `mysql` 계정으로 돌고 있다. 아무도 로그인한 적 없지만 잘 돈다. 목적은 앱이 뚫렸을 때 공격자가 얻는 것을 "서버 전체"가 아니라 "`ledger` 가 만질 수 있는 것"으로 좁히는 것
    - **비번을 만들지 않는다** — `/etc/shadow` 두 번째 칸이 `!`(잠김). systemd 는 root 로 돌다가 `User=ledger` 로 **내려가는** 것이라 인증 절차 자체가 없다. 비번을 만들면 막아지는 경로 없이 관리할 비밀만 하나 는다 — ADR-043 에서 MySQL root 에 내린 판단과 같은 논리
    - 셸이 없어도 `sudo -u ledger <명령>` 은 된다. 막히는 건 대화형 로그인(`su - ledger`)뿐이라 디버깅에 지장 없음
    - `/etc/passwd` 의 `x` 는 "비번 없음"이 아니라 "해시는 `/etc/shadow` 에 있다"는 표시. `passwd` 는 누구나 읽을 수 있어서 해시를 root 전용 파일로 옮긴 결과
  - 이 단계가 못 막는 것 — 앱이 뚫리면 `ledger_db` 안은 그대로 털린다 (ADR-043 "감수"). 전용 유저는 DB **밖의** 서버를 지키는 장치다
  - 설치 후 `free -h` available **915Mi** (2-2 직후 879Mi). JRE 는 깔아둔 것만으론 메모리를 쓰지 않는다 — 실제 판단은 2-5 에서 앱을 올린 뒤
- **2-4 systemd — ✅ 2026-09-18** — `ExecStart` 는 `java -jar`, `Restart=always`(운영 3종의 "자동 재시작"이 여기서 같이 해결), `User=ledger`.
  환경변수는 `EnvironmentFile=`(권한 600)에 — `SPRING_PROFILES_ACTIVE=prod` / `DB_USERNAME` / `DB_PASSWORD` / `JWT_SECRET`
  - **자리 결정** — jar 는 `/opt/ledger/`, 설정은 `/etc/ledger/ledger.env`
    - `/opt` — 패키지 매니저 밖에서 온 자체 완결 소프트웨어의 자리(FHS). apt 로 깐 MySQL·Java 는 `/usr` 밑, 직접 올리는 jar 는 `/opt`
    - `/etc` — 설정의 자리(nginx → `/etc/nginx`, MySQL → `/etc/mysql`). **나누는 이유는 수명이 다르기 때문** — jar 는 배포마다 갈아끼우고 비밀값은 서버가 사는 동안 그대로. 같은 폴더에 두면 3단계 CD 가 `/opt/ledger` 를 비우다 비밀값을 같이 지우는 사고가 난다
    - `/etc/default/ledger` 가 아닌 이유 — 그 자리는 배포판 패키지 관례. 직접 올린 앱은 자기 이름의 디렉토리를 갖는다
    - 실무 규모에선 파일 대신 Secrets Manager·Parameter Store 에서 기동 시 받아온다. 한 대짜리엔 과함 — "지금은 파일 + 600, 서버가 늘면 Parameter Store"
  - **소유권** — `ledger.env` 는 `root:root 600`. systemd(PID 1, root)가 유닛을 준비하며 파일을 읽고 값을 환경변수로 넘긴 **뒤에** `User=ledger` 로 내려가므로 앱 계정은 이 파일을 읽을 필요가 없다. `/opt/ledger` 는 올리는 쪽(지금은 `ubuntu`, 3단계부터 배포 계정) 소유 755, jar 644 — **앱은 자기 실행 파일을 고칠 수 없어야 한다**(뚫린 앱이 jar 를 바꿔치기하는 경로 차단)
  - `JWT_SECRET` 형식 — 코드가 `Keys.hmacShaKeyFor(secret.getBytes())` 로 문자열 바이트를 그대로 키로 쓴다(2026-09-18 grep). 32바이트 이상이면 HS256, 64바이트 이상이면 HS512. `openssl rand -base64 48`(64글자) 로 만들면 된다. base64 는 `#`·공백이 없어 EnvironmentFile 에 따옴표 없이 넣어도 안전
  - **실측 (2026-09-18)** — `/etc/ledger` `drwxr-xr-x root root` / `/opt/ledger` `drwxr-xr-x ubuntu ubuntu` / `ledger.env` `-rw------- root root`.
    값 4개는 `sudo awk -F= '{print $1, length($2)}'` 로 **이름과 길이만** 확인(값은 화면·채팅에 띄우지 않는다) — `SPRING_PROFILES_ACTIVE 4` / `DB_USERNAME 10` / `DB_PASSWORD 32` / `JWT_SECRET 64`
    JWT 시크릿은 `openssl rand -base64 48`. `ledger.env` 는 `=` 양옆 공백·따옴표 없이, 값에 `#` 가 있으면 systemd 가 주석으로 보므로 그 줄만 큰따옴표
  - **유닛 파일** `/etc/systemd/system/ledger.service` — `Type=simple` / `User`·`Group=ledger` / `WorkingDirectory=/opt/ledger` / `EnvironmentFile=/etc/ledger/ledger.env` / `ExecStart=/usr/bin/java -jar /opt/ledger/ledger.jar` / `Restart=always` + `RestartSec=5` / `SyslogIdentifier=ledger` / `WantedBy=multi-user.target`
    - `After=network-online.target mysql.service` 만 쓰고 **`Requires=` 는 안 쓴다** — `Requires` 는 "MySQL 이 죽으면 나도 죽어라" 까지라 MySQL 재시작마다 앱이 같이 내려간다. 순서만 정하고 접속 실패는 `Restart=always` 가 재시도로 흡수
    - `RestartSec=5` 가 없으면 기동 실패 시 초당 수십 번 재시도하며 로그를 태운다
    - `ExecStart` 는 **절대경로 필수** — systemd 는 셸이 아니라 `PATH` 를 보지 않는다. `/usr/bin/java` 는 `/etc/alternatives/java` 심볼릭 링크(데비안 alternatives)지만 systemd 가 따라간다. 나중에 다른 JDK 를 깔면 이 스위치가 옮겨갈 수 있음
    - **jar 이름을 `ledger.jar` 로 고정** — 빌드 산출물은 `ledger-0.0.1-SNAPSHOT.jar`. 버전이 파일명에 박히면 버전 올릴 때마다 유닛 파일을 고쳐야 한다. 올릴 때 이름을 바꿔 두면 유닛 파일은 영원히 그대로 (ETC)
    - 보안 4줄 — `NoNewPrivileges`(도중 권한 상승 차단) / `PrivateTmp`(전용 `/tmp`) / `ProtectSystem=full`(`/usr`·`/boot`·`/etc` 읽기 전용) / `ProtectHome`(`/home` 비노출). 앱은 자기 디렉토리 읽기 + MySQL 접속이 전부라 넷 다 걸어도 지장 없다. 실무 유닛 파일의 기본 세트
    - `EnvironmentFile` 은 `ProtectSystem` 과 무관 — systemd(root)가 샌드박스를 걸기 **전에** 읽어 환경변수로 넘긴다
  - **등록** — `systemd-analyze verify`(우리 파일 지적 0줄 = 통과. `xfs_scrub_all` 경고는 우분투 기본 유닛이라 무시) → `daemon-reload`(디스크를 다시 읽어라. 유닛 파일 만들거나 고칠 때마다) → `enable`(부팅 시 자동 기동 등록 — `multi-user.target.wants/` 에 심볼릭 링크) → `is-enabled` 가 `enabled`
    - **`enable` ≠ `start`** — `enable` 은 "앞으로 부팅할 때마다", `start` 는 "지금". 별개라서 하나만 하면 반쪽이 된다. 환경변수는 `start` 하는 순간 읽힌다
    - 여기서 **운영 3종의 "자동 재시작"이 닫혔다** — 앱이 죽으면 `Restart=always`, 서버가 재부팅되면 `enable`
  - 남은 것 — jar 가 없어 `start` 는 2-5 에서
  - ADR-046 후보 — "설정은 `/etc`, 실행 파일은 `/opt`, 비밀값 파일은 root 소유" (문제 → 대안 → 근거 → 감수 로 정리)

### 3단계 가이드 — CD 최소판 (게이트 없이)

- `ci.yml` 에 `deploy` 잡 추가. `needs: build` + **push to main 일 때만**(PR 에선 배포 금지) 조건

    **문자열 그대로 매칭**이라 워크플로도 정확히 `sudo systemctl restart ledger` 로 불러야 한다 (`ledger.service` 로 쓰면 인자가 달라 거부)

    - `/etc/sudoers.d` 는 750 root 라 일반 계정은 **파일 존재 여부조차 못 본다**(`ls` 가 Permission denied — 정상. 공격자에게 권한 지도를 주지 않으려는 것)

  - 유닛 파일 mtime(21:03)이 2-4 의 `daemon-reload` 보다 나중이라 `changed on disk` 경고가 떠 있었다 → `daemon-reload` 로 해소. `deploy` 는 reload 권한이 없으므로 `ubuntu` 로 한다
  - **`systemctl status` 의 `active` 는 "앱이 떴다"는 뜻이 아니다** — restart 직후 `active (running)` 인데 Memory 1.9M(앱은 약 300Mi). `Type=simple` 은 **프로세스를 실행한 순간**을 성공으로 친다. 기동 실패해도 `Restart=always` 가 5초마다 다시 띄워 한동안 `active` 로 보인다.

- **3-7 보강 ✅ (2026-09-20)** — CD 가 1회 성공한 직후라 이제 붙였다 (같이 넣었으면 첫 실패의 원인 후보가 늘었을 것)
  - **호스트 키 고정** — Secret `EC2_HOST_KEY`(`ssh-ed25519 AAAA…` 한 줄, 81바이트) → 워크플로가 `known_hosts` 를 미리 쓰고 `StrictHostKeyChecking=yes`(3곳).
    값은 `ssh-keyscan` 이 아니라 **내 맥의 `known_hosts` 에서** 꺼냈다(`ssh-keygen -F <EC2_HOST>`) — keyscan 은 지금 네트워크가 돌려주는 값을 그냥 받는 것이라, 검증하려는 걸 검증 없이 가져오는 셈. 2-1 첫 접속 때 믿기로 한 값을 쓴다.
    **서버를 새로 만들면 지문이 바뀐다 → 배포가 `Host key verification failed` 로 멈춘다(정상). 그때 Secret 을 갱신**
  - **호스트 키 1차 실패 (CI #50)** — `No ED25519 host key is known for *** and you have requested strict checking` → `Host key verification failed`.
    build 는 새 액션 버전으로 통과, deploy 는 전송 직전에 멈춤(22번은 `always` 로 닫힘, 서버 무변경). **ssh 는 `known_hosts` 의 형식이 틀린 줄을 조용히 무시**해서 "키가 없다"고만 말한다 — 값이 잘렸는지 밖에서 안 보인다.
    → 워크플로에 **상시 검사**를 넣었다: `ssh-keygen -l -f known_hosts` 가 실패하면 길이(정상 80)와 앞 11글자를 찍고 중단. 임시 디버그가 아니라 남겨 둘 검사다(3-6 의 "밖에서 안 보이는 값은 길이·접두를 찍는다" 를 미리 심어 둔 것)
    **원인은 값이 아니라 확인 절차였다** — 키를 `pbcopy` 한 뒤, 채팅에서 확인 명령(`pbpaste | wc -c`, 정확히 15글자)을 복사하는 순간 클립보드가 덮어써졌다. 두 방법(known_hosts·서버 원본) 모두 "15"가 나온 이유. → 복사와 확인을 한 줄로: `… | tee >(pbcopy) | wc -c` (80 출력 + 클립보드 유지). **클립보드에 값을 넣은 뒤엔 다른 걸 복사하지 않는다**
    **CI #51 ✅ (`e636d42`)** — 지문 검사 통과 → `StrictHostKeyChecking=yes` 로 접속 → 전송 10초 · 헬스 11초 · 22번 닫힘. 호스트 키 검증이 실제로 동작한다
  - **액션 전부 SHA 고정** — build 잡의 `checkout`(v4 → v7.0.1) · `setup-java`(v4 → v6.0.1)까지. 태그 고정 0건
  - **Dependabot** — `.github/dependabot.yml`(github-actions, weekly). SHA 고정의 단점(수동 업데이트)을 없앤다. PR 에선 build 만 돌고 deploy 는 main push 조건이라 안 돈다

### 5단계 메모 — 도메인은 HTTPS 직전에 산다

- IP 주소만으로는 뒤 기능이 막힌다 — HTTPS 인증서(사실상 도메인 필요) / PWA 설치(HTTPS 필수) / 카카오맵·네이버·구글 콘솔 등록 / Refresh 쿠키 `Secure`(ADR-010)
- 구조 — 사용자 → Nginx(80 은 443 으로 돌려보냄, 443 에서 인증서 처리) → `localhost:8080`. 보안 그룹에 80·443 만 열어둔 이유 (aws-인프라.md)
- 도메인이 생기면 `application-prod.yml` 을 처음 만들 시점일 수 있다 (쿠키 `Secure`, CORS 등 운영 전용 값 — ADR-042)

#### 진행 기록 (5단계)

- **5-1 도메인 ✅ (2026-09-21) — `dotoree.app`** (Cloudflare Registrar, 연 $14.20, 자동 갱신)
  - **등록기관 Cloudflare** — 원가 판매라 갱신가가 안 뛴다 · WHOIS 가림 기본 · DNS 화면이 같은 곳. 감수: 네임서버를 Cloudflare 밖으로 못 바꾼다(Route 53 으로 옮기려면 도메인 이전 — 등록 후 60일 잠김). A·CNAME·TXT 몇 줄이면 되는 지금 규모엔 무관
  - **이름** — 가계부가 드러나는 2단어 영어 조합(`snapledger`·`homeledger` …)은 `.com`·`.app` 모두 선점. 특히 `ledger` 는 같은 이름의 암호화폐 지갑 회사 때문에 거의 다 잡혀 있다.
    기능을 설명하는 이름 대신 **서비스가 이름에 뜻을 채우는 쪽**(토스·당근과 같은 방식)으로 바꿨다. 도토리 = 다람쥐가 모으는 것 + 싸이월드 화폐
    - 후보는 등록 가능 여부와 함께 **같은 이름의 앱·서비스가 있는지**를 먼저 검색했다 — `찰칵`(찰칵장부 앱), `receipi`(일본 영수증 가계부 앱), `wonlog`(쇼핑몰)가 여기서 탈락
    - 철자 — 표준 표기 `dotori` 는 선점, `dotoree` 는 변형이다. 말로 불러주면 받아적기 어렵다 → **주소는 링크로 건넨다**
  - **TLD `.app`** — `dotoree.com` 은 원래 주인이 있고 만료 후 redemption(유예) 기간이라 살 수 없었다(RDAP 조회. 공개 검색 페이지는 "구매 가능"으로 잘못 보여줬고 로그인한 대시보드가 맞았다).
    `.app` 은 브라우저에 **HSTS preload** 로 박혀 있어 HTTPS 가 아니면 아예 안 열린다 — 돈·개인정보를 다루는 서비스라 오히려 맞다. 대신 5-2(Nginx 80)는 도메인이 아니라 `curl` 로 확인한다
  - **DNS** — `A @` → 탄력적 IP, `CNAME www` → `dotoree.app`, 둘 다 **DNS only(회색 구름)**. 확인 `dig +short` 두 이름 모두 IP(출력은 IP 라 기록하지 않음)
  - 값 분류(ADR-048) — 도메인 이름은 **공개 설정**(yml·문서에 그대로). Cloudflare 계정·2FA 백업 코드는 비밀(개인 보관처). 등록자 연락처는 ICANN 규정상 실정보, WHOIS 엔 Cloudflare 가 가려서 내보낸다
- **5-2 Nginx ✅ (2026-09-21)** — apt `nginx` **1.28.3**. 설치만으로 `enabled`. 메모리 8.3M, 설치 후 available 651Mi(스왑 불필요 그대로)

        - 우리가 만든 고정 이미지(로고·소개 화면) → 저장소 `static/` 에 두고 jar 에 포함. 코드와 같이 버전 관리되고 배포하면 같이 올라간다. S3 아님
